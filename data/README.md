# DAP 문제은행 데이터

`index.html` 은 이 폴더의 파일들을 읽어서 문제은행을 구성한다.

```
data/
  manifest.js                       과목 정의 + 읽어들일 팩 파일 목록 + 묶음(collection) 정의
  1.전사아키텍처이해.core.js          과목 1 기본 팩 (100문항)
  2.데이터요건분석.core.js            과목 2 기본 팩 (100문항)
  3.데이터표준화.core.js              과목 3 기본 팩 (100문항)
  4.데이터모델링.core.js              과목 4 기본 팩 (250문항)
  5.데이터베이스설계와이용.core.js     과목 5 기본 팩 (100문항)
  6.데이터품질관리이해.core.js         과목 6 기본 팩 (100문항)
  N.<과목명>.v2.js                    기본 문제은행 ver 2 — 실제 출제 유형으로 새로 쓴 것 (묶음 "v2")
```

`*.v2.js` 는 손으로 고치지 않는다. 원고 `tools/v2-src/chN*.txt` 를 고치고
`node tools/v2-build.js <과목> --write` 로 다시 만든다(인자 없이 `--write` 를 빼면 점검 통계만 낸다).
v2 는 정답이 하나인 문항만 둔다 — 실제 시험에 복수 선택 문항이 없기 때문이다(`test/pack-format.js` 가 막는다).

## 파일 이름 규칙

`<과목번호>.<과목명>.<팩이름>.js` 형태로 짓는다. 앞의 번호는 정렬 순서를 위한 것이고,
맨 뒤의 `core` / `extra1` 은 팩 이름이다. 파일 이름 자체는 앱 동작에 영향을 주지 않는다.
실제로 쓰이는 값은 파일 안의 `chapter` 와 `pack` 이고, 읽어들일 파일 목록은
`manifest.js` 의 `files` 배열이 결정한다.

## 인코딩

모든 파일은 **UTF-8 (BOM 없음)** 으로 저장한다. 다른 인코딩(EUC-KR/CP949)으로
저장하면 한글이 깨진다. VS Code 오른쪽 아래 인코딩 표시가 `UTF-8` 인지 확인할 것.
파일 이름에도 한글이 들어가므로, 새 팩을 만들 때 이름을 직접 타이핑하기보다
기존 파일을 복사해서 고치는 편이 안전하다.

## 문항 스키마

| 필드 | 설명 |
|---|---|
| `id` | 전체 은행에서 **유일한** 문항 ID. 중복되면 나중 문항이 무시된다 |
| `ch` | 과목 번호 (1~6). `chapter` 값과 달라도 `chapter` 로 교정된다 |
| `no` | 과목 안에서의 표시 번호. 비워두면 자동 부여 |
| `q` | 문제 지문. `\n` 으로 줄바꿈 가능 |
| `c` | 보기 배열 (4개. 외부 원본 묶음은 원본 오류를 바로잡느라 5개인 문항이 있다 — D13-158) |
| `a` | 정답 인덱스, **0부터 시작** (첫 보기가 정답이면 `0`) |
| `e` | 해설 |
| `s` | 원천 안의 파트(장·절 이름). 화면에 나오고 취약 영역 분석에도 쓰인다 |
| `r` | 원천 자료를 말로 적은 것. 없으면 팩의 `source`. **화면에는 안 나온다** |
| `rf` | `data_source/` 의 파일 이름. 없으면 팩의 `sourceFiles`. 문자열이나 배열 |
| `m` | `1` 이면 "모두 고르시오" 문항. 보기를 여러 개 고른 뒤 채점하고, `a`(배열)와 **똑같아야** 정답 |

`a` 는 인덱스 하나가 기본이다. 배열도 받는다.

- `m: 1` 과 함께 — "모두 고르시오". 고른 것이 정답 집합과 같아야 맞다. 정답이 하나뿐인
  "모두 고르시오" 문항도 배열(`[3]`)로 둔다. 몇 개인지 알려 주지 않기 위해서다
- `m` 없이 — 복수 정답 인정. 원본의 정답이 정정되어 둘 다 맞는 경우다. 하나만 골라도 맞다

고른 답(`session.ans` · `S.stats[id].pick` · 응시 기록 `answers`)도 같은 모양이다 —
단일 문항은 번호, "모두 고르시오" 문항은 정렬된 번호 배열.
정오 판정은 앱의 `isRight(q, pick)` 한 곳에서만 한다. `=== q.a` 로 비교하지 말 것.

## 지문 서식 — 그림·표·상자

원본에 그림이나 표가 있는 문항(실전문제 2013)은 `q` · `c` · `e` 안에 간단한 표기를 쓴다.
앱의 `rich()` 가 그린다. **표기가 없는 문항은 전과 똑같이 글자 그대로 나온다.**

| 표기 | 뜻 |
|---|---|
| `[[img:키]]` (한 줄 단독) | 그림. 팩 머리의 `images: { 키: "data:image/…;base64,…" }` 에서 찾는다 |
| `:::` … `:::` | 테두리 상자 (원본의 「아 래」 상자). 안에 표·그림이 들어갈 수 있다 |
| ` ``` ` … ` ``` ` | 고정폭 (SQL · 실행계획) |
| `\| 셀 \| 셀 \|` | 표 한 행. 이어진 행이 한 표가 된다. 첫 행을 `‖ ` 로 시작하면 머리행. 셀 안 줄바꿈은 `¶` |
| `아 래` (한 줄 단독) | 원본의 「아 래」 표지 |

그림 키는 전체 은행에서 유일해야 한다(`window.DAP_IMG` 하나에 모인다).
그림은 팩 안에 data URI 로 넣는다 — 암호문 팩이면 그림도 함께 잠긴다.
`test/pack-format.js` 가 `[[img:…]]` 가 팩의 `images` 에 있는지 대조한다.

## 원천 표기 — 해설 아래 한 줄

틀린 문항을 다시 볼 때 필요한 것은 두 가지뿐이다. **어느 파일**이고 **그 안의 어느 파트**인가.
그래서 해설 아래에 이 둘만 붙는다.

```
원천   1장 1절 IOT와 클러스터                        ← s (파트)
       V. 데이터베이스 설계와 이용.hwpx   [요약본]     ← rf / 팩의 sourceFiles (파일)
       5과목. 데이터베이스 설계와 이용.pdf [강의자료]
```

파일 이름은 `data_source/` 의 실제 이름과 글자 그대로 같아야 원문을 찾을 수 있다.
대괄호 안의 자료 종류(교재·요약본·강의자료·워드 요약)는 앱이 파일 이름에서
가려내 붙인다. 데이터에 적지 않는다.

`r` / 팩의 `source` 는 같은 문서를 말로 옮긴 것이라 **화면에 나오지 않는다.**
팩을 읽는 사람을 위한 기록으로만 남아 있다.

팩 전체가 같은 자료를 봤으면 팩 머리에 한 번만 적는다.

```js
DAP_BANK.add({
  chapter: 4,
  pack: "extra1",
  source: "요약본 「IV. 데이터 모델링」",
  sourceFiles: [
    "IV. 데이터 모델링.hwpx"
  ],
  questions: [ … ]
});
```

일부 문항만 다른 자료를 봤다면 그 문항에 `r` · `rf` 를 달아 덮어쓴다.
외부 연습문제 팩처럼 로컬 파일 근거가 없는 팩은 둘 다 비워 두면 줄이 나오지 않는다.

### 팩의 `sourceFiles` 는 "이 팩이 본 자료"이지 "모든 문항에 다 있는 자료"가 아니다

팩 머리에 파일을 둘 적어 두면 팩 안의 **모든** 문항이 그 둘을 함께 주장한다.
그런데 한쪽에만 있는 대목이 많다. 그런 문항은 `rf` 로 실제 있는 파일만 남긴다.

```js
// 팩 머리는 가이드 + 요약본 둘 다지만,
// 이 문항의 "전용"은 가이드에만 나온다
{ "id": "C4-178", …, "s": "2장 5절 속성 정의 시 유의 사항",
  "rf": ["[데이터 전문가 포럼] 데이터아키텍처 준전문가 가이드(2020.08.29.).hwpx"] }
```

원천을 적는 이유는 그 파일을 펼쳐 다시 읽기 위해서다. 없는 것을 가리키면
펼쳐 봐야 찾지 못하니 없느니만 못하다. 문항을 더하거나 팩의 `sourceFiles` 를
고친 뒤에는 `node tools/source-check.js` 로 대조할 것.
2026-09-10 에 이 대조로 108문항의 거짓 표기를 걷어냈다.

**가이드와 다른 자료는 잣대가 다르다.** 가이드는 시험 범위 전체를 담은 교재라
어느 대목이든 조금씩은 걸리고 분량도 서너 배여서, 점수를 맞대 놓으면 정작 그
대목을 다루는 요약본·강의자료가 밀려난다. 그래서 도구는 **가이드만 자동으로 빼고**,
그 밖의 자료는 「확인 요망」으로만 알린다. 구가 안 걸리는 것과 그 대목이 없는 것은
다른 이야기이기 때문이다 — 요약본은 같은 내용을 풀어 쓴다. 원문을 열어 보고 뺄 것.

## 문항 블록 (학습 단위)

과목 화면의 [문항 블록] 표는 문항을 앞에서부터 일정 개수씩 잘라 보여준다.
그 크기는 `manifest.js` 의 `blockSize` 가 정한다.

| 과목 | 시험 출제 수(`perSet`) | 블록 크기(`blockSize`) |
|---|---|---|
| 1·2·3·5·6 | 10 | 20 |
| 4 데이터 모델링 | 25 | 25 |

블록은 **시험 출제 단위의 정수배**로 둔다. 그래야 블록 하나를 푸는 것이
시험 몇 회분을 푸는 것과 같은 감각이 된다. `blockSize` 를 생략하면
`perSet` 의 2배를 쓴다. 같은 과목 화면의 [무작위 N문항] 버튼도 이 값을 따른다.

블록 크기를 바꿔도 풀이 기록은 그대로다. 기록은 문항 id 기준이라 블록 경계와
무관하기 때문이다. 다만 예전 경계로 만들어진 "블록 이어풀기" 위치는 지금 블록과
맞지 않으므로 앱이 처음 뜰 때 정리한다.

## 내용정리 (`data/notes/`)

문제은행과 별개인 읽기 화면의 데이터다. **두 판**이 있고, 과목마다 파일 하나와 그림 폴더가 있다.

- **2020 판** — 교재 요약본(I.~VI. hwpx)을 옮긴 것. 여섯 과목
- **2013 판** — 준전문가 가이드(교재) 본문을 개조식으로 정리한 것(I~IV). 가이드에 없는 V·VI 는 2013 워드 요약(.doc)으로,
  I~IV 에 워드 요약에서 보탠 내용은 원고에 `{w}` 를 달아 「✎워드」 배지로 보인다

```
data/notes/
  3.데이터표준화.js     DAP_NOTES.add({ ch, title, images, chapters:[{ no, title, sections:[{ no, title, intro, items }] }] })
  img/III-01.jpg …      그림. 파일 이름이 원고의 [[img:키]] 다
  2013/1.전사아키텍처이해.js   2013 판. DAP_NOTES.add({ ed:"2013", ch, … }) — ed 가 없으면 2020 판으로 받는다
  img2013/G1-01.jpg …   2013 판 그림 (G{과목}-NN)
```

`*.js` 는 손으로 고치지 않는다. 원고를 고치고 다시 만든다(원고 형식은 도구 머리 주석).

- 2020 판 : `tools/notes-src/chN.md` → `node tools/notes-build.js <과목> --write`
- 2013 판 : `tools/notes-src/2013/chN.md` → `node tools/notes-build.js <과목> --ed 2013 --write`

새 과목은 `manifest.js` 의 `notes` 에 `{ ch, file }`(2013 판은 `{ ed: "2013", ch, file }`)을 더하면
그 판 화면의 「준비 중」이 풀린다.
과목 파일은 그 과목을 처음 열 때 읽으므로 문제은행 시작 속도에는 영향이 없다.

문항의 `s` 가 요약본의 「N장 M절 …」 체계를 따르면 2020 판 절 화면의 [이 절의 문항]에 모이고,
해설의 원천 줄에 [2020 Edition 에서 보기]가 붙는다. `node test/notes.js` 가 이 연결을 전수 대조한다.
2013 판은 장·절 번호 체계가 요약본과 달라 문항과 잇지 않는다.

## 실기 (`data/dm/`)

「실기」 화면의 데이터 — Data Modeling(실기) 실습문제 30개의 요구 사항 지문과 모범 답안 ERD.
`manifest.js` 의 `dm: "dm/dm.js"` 가 가리키고, 「실기」 화면을 처음 열 때 읽는다.

```
data/dm/
  dm.js            DAP_DM.add({ title, levels:[기초…특급], images:{ 키:{src,w,h} },
                     items:[{ id, lv, grp, title, stars, q:[블록], a:[블록] }] })
  img/dm-01.png …  ERD. 원본 크기 그대로(확대 보기에서 키워 보므로 줄이지 않는다)
```

블록은 `{p}` 문단 · `{h}` 소제목 · `{img, cap}` 그림 · `{tbl, kv}` 표 · `{task}` 함께 작성할 것(지문 끝).
`q` 가 지문, `a` 가 모범 답안이다. `dm.js` 는 손으로 고치지 않는다 —
`data_source/Data Modeling(실기)/Modeling 실습문제.hwpx` → `node tools/dm-build.js --write`.
원문 오타 수정·그림 제목 등 원본과 다르게 둔 것은 도구 머리의 `FIX`·`ANSWER_AT`·`CAPTION` 에 있다.
`node test/dm.js` 가 파일·그림·그리기를 점검한다.

## 새 과목 추가

`manifest.js` 의 `chapters` 에 항목을 추가하고 팩 파일을 만들면 된다.
`perSet` 합계가 `exam.totalQuestions` 와 맞도록 조정하고, `blockSize` 는
그 `perSet` 의 정수배로 둔다.
