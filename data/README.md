# DAP 문제은행 데이터

`index.html` 은 이 폴더의 파일들을 읽어서 문제은행을 구성한다.

```
data/
  manifest.js                       과목 정의 + 읽어들일 팩 파일 목록
  1.전사아키텍처이해.core.js          과목 1 기본 팩 (100문항)
  2.데이터요건분석.core.js            과목 2 기본 팩 (100문항)
  3.데이터표준화.core.js              과목 3 기본 팩 (100문항)
  4.데이터모델링.core.js              과목 4 기본 팩 (250문항)
  5.데이터베이스설계와이용.core.js     과목 5 기본 팩 (100문항)
  6.데이터품질관리이해.core.js         과목 6 기본 팩 (100문항)
```

## 파일 이름 규칙

`<과목번호>.<과목명>.<팩이름>.js` 형태로 짓는다. 앞의 번호는 정렬 순서를 위한 것이고,
맨 뒤의 `core` / `extra1` 은 팩 이름이다. 파일 이름 자체는 앱 동작에 영향을 주지 않는다.
실제로 쓰이는 값은 파일 안의 `chapter` 와 `pack` 이고, 읽어들일 파일 목록은
`manifest.js` 의 `files` 배열이 결정한다.

## 인코딩

모든 파일은 **UTF-8 (BOM 없음)** 으로 저장한다. 다른 인코딩(EUC-KR/CP949)으로
저장하면 한글이 깨진다. VS Code 오른쪽 아래 인코딩 표시가 `UTF-8` 인지 확인할 것.
파일 이름에도 한글이 들어가므로, 새 팩을 만들 때 이름을 직접 타이핑하기보다
기존 파일을 복사해서 고치는 편이 안전하다.

## 문항 추가하기

### 1. 기존 팩에 이어붙이기

팩 파일의 `questions` 배열 끝에 항목을 추가하면 된다.

### 2. 새 팩 파일 만들기 (권장)

과목 4에 문항을 더 넣는 경우:

**data/4.데이터모델링.extra1.js**

```js
DAP_BANK.add({
  chapter: 4,
  pack: "extra1",
  questions: [
    {
      "id": "C4X-001",
      "ch": 4,
      "no": 251,
      "q": "문제 지문",
      "c": ["보기1", "보기2", "보기3", "보기4"],
      "a": 2,
      "e": "해설",
      "s": "4장 3절 논리 데이터 모델링"
    }
  ]
});
```

그리고 `manifest.js` 의 `files` 배열에 파일명을 추가한다.

```js
files: [
  "1.전사아키텍처이해.core.js",
  "2.데이터요건분석.core.js",
  "3.데이터표준화.core.js",
  "4.데이터모델링.core.js",
  "4.데이터모델링.extra1.js",
  "5.데이터베이스설계와이용.core.js",
  "6.데이터품질관리이해.core.js"
]
```

`index.html` 을 새로고침하면 과목 4가 251문항으로 늘어난다.

## 문항 스키마

| 필드 | 설명 |
|---|---|
| `id` | 전체 은행에서 **유일한** 문항 ID. 중복되면 나중 문항이 무시된다 |
| `ch` | 과목 번호 (1~6). `chapter` 값과 달라도 `chapter` 로 교정된다 |
| `no` | 과목 안에서의 표시 번호. 비워두면 자동 부여 |
| `q` | 문제 지문. `\n` 으로 줄바꿈 가능 |
| `c` | 보기 배열 (4개) |
| `a` | 정답 인덱스, **0부터 시작** (첫 보기가 정답이면 `0`) |
| `e` | 해설 |
| `s` | 원천 안의 파트(장·절 이름). 화면에 나오고 취약 영역 분석에도 쓰인다 |
| `r` | 원천 자료를 말로 적은 것. 없으면 팩의 `source`. **화면에는 안 나온다** |
| `rf` | `data_source/` 의 파일 이름. 없으면 팩의 `sourceFiles`. 문자열이나 배열 |

## 원천 표기 — 해설 아래 한 줄

틀린 문항을 다시 볼 때 필요한 것은 두 가지뿐이다. **어느 파일**이고 **그 안의 어느 파트**인가.
그래서 해설 아래에 이 둘만 붙는다.

```
원천   1장 1절 IOT와 클러스터                        ← s (파트)
       V. 데이터베이스 설계와 이용.hwpx   [요약본]     ← rf / 팩의 sourceFiles (파일)
       5과목. 데이터베이스 설계와 이용.pdf [강의자료]
```

파일 이름은 `data_source/` 의 실제 이름과 글자 그대로 같아야 원문을 찾을 수 있다.
대괄호 안의 자료 종류(교재·요약본·강의자료·워드 요약)는 앱이 파일 이름에서
가려내 붙인다. 데이터에 적지 않는다.

`r` / 팩의 `source` 는 같은 문서를 말로 옮긴 것이라 **화면에 나오지 않는다.**
팩을 읽는 사람을 위한 기록으로만 남아 있다.

팩 전체가 같은 자료를 봤으면 팩 머리에 한 번만 적는다.

```js
DAP_BANK.add({
  chapter: 4,
  pack: "extra1",
  source: "요약본 「IV. 데이터 모델링」",
  sourceFiles: [
    "IV. 데이터 모델링.hwpx"
  ],
  questions: [ … ]
});
```

일부 문항만 다른 자료를 봤다면 그 문항에 `r` · `rf` 를 달아 덮어쓴다.
외부 연습문제 팩처럼 로컬 파일 근거가 없는 팩은 둘 다 비워 두면 줄이 나오지 않는다.

### 팩의 `sourceFiles` 는 "이 팩이 본 자료"이지 "모든 문항에 다 있는 자료"가 아니다

팩 머리에 파일을 둘 적어 두면 팩 안의 **모든** 문항이 그 둘을 함께 주장한다.
그런데 한쪽에만 있는 대목이 많다. 그런 문항은 `rf` 로 실제 있는 파일만 남긴다.

```js
// 팩 머리는 가이드 + 요약본 둘 다지만,
// 이 문항의 "전용"은 가이드에만 나온다
{ "id": "C4-178", …, "s": "2장 5절 속성 정의 시 유의 사항",
  "rf": ["[데이터 전문가 포럼] 데이터아키텍처 준전문가 가이드(2020.08.29.).hwpx"] }
```

원천을 적는 이유는 그 파일을 펼쳐 다시 읽기 위해서다. 없는 것을 가리키면
펼쳐 봐야 찾지 못하니 없느니만 못하다. 문항을 더하거나 팩의 `sourceFiles` 를
고친 뒤에는 `node tools/source-check.js` 로 대조할 것.
2026-09-10 에 이 대조로 108문항의 거짓 표기를 걷어냈다.

**가이드와 다른 자료는 잣대가 다르다.** 가이드는 시험 범위 전체를 담은 교재라
어느 대목이든 조금씩은 걸리고 분량도 서너 배여서, 점수를 맞대 놓으면 정작 그
대목을 다루는 요약본·강의자료가 밀려난다. 그래서 도구는 **가이드만 자동으로 빼고**,
그 밖의 자료는 「확인 요망」으로만 알린다. 구가 안 걸리는 것과 그 대목이 없는 것은
다른 이야기이기 때문이다 — 요약본은 같은 내용을 풀어 쓴다. 원문을 열어 보고 뺄 것.

## 문항 블록 (학습 단위)

과목 화면의 [문항 블록] 표는 문항을 앞에서부터 일정 개수씩 잘라 보여준다.
그 크기는 `manifest.js` 의 `blockSize` 가 정한다.

| 과목 | 시험 출제 수(`perSet`) | 블록 크기(`blockSize`) |
|---|---|---|
| 1·2·3·5·6 | 10 | 20 |
| 4 데이터 모델링 | 25 | 25 |

블록은 **시험 출제 단위의 정수배**로 둔다. 그래야 블록 하나를 푸는 것이
시험 몇 회분을 푸는 것과 같은 감각이 된다. `blockSize` 를 생략하면
`perSet` 의 2배를 쓴다. 같은 과목 화면의 [무작위 N문항] 버튼도 이 값을 따른다.

블록 크기를 바꿔도 풀이 기록은 그대로다. 기록은 문항 id 기준이라 블록 경계와
무관하기 때문이다. 다만 예전 경계로 만들어진 "블록 이어풀기" 위치는 지금 블록과
맞지 않으므로 앱이 처음 뜰 때 정리한다.

## 새 과목 추가

`manifest.js` 의 `chapters` 에 항목을 추가하고 팩 파일을 만들면 된다.
`perSet` 합계가 `exam.totalQuestions` 와 맞도록 조정하고, `blockSize` 는
그 `perSet` 의 정수배로 둔다.
