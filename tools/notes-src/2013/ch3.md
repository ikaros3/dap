# 제1장 데이터 표준화 개요
## 제1절 데이터 표준화 필요성
### 1. 데이터 관리 현황 및 개선 방안
- 데이터가 전략적 의사결정의 핵심 요소로 대두 → 데이터 통합 및 데이터 품질에 대한 관심 증대
- 데이터 품질 확보를 위해 **데이터 표준화가 필수적으로 수반**되어야 함
- 그러나 다음과 같은 현실적 문제점이 정확한 정보를 적시에 전달하는 데 장애 요인
#### 가. 데이터 활용상의 문제점
- **데이터의 중복 및 조직, 업무, 시스템별 데이터 불일치 발생**
  - 표준 정책 미비로 동일한 의미의 데이터를 다른 명칭으로 중복 관리하거나, 동일한 명칭의 데이터를 시스템 간에 상이한 로직으로 산출하여 다른 의미로 활용
- **데이터에 대한 의미 파악 지연으로 정보 제공의 적시성 결여**
  - 데이터 명칭·정의의 표준 미관리로 새로운 정보 요건이나 변경 시 필요 데이터 파악에 많은 시간 낭비
- **데이터 통합의 어려움**
  - 단위 시스템 위주로 표준을 적용하거나 적용하지 않아, 전사 데이터웨어하우스 구축 등 통합 정보 요건 기반 시스템 구축 시 의미 파악과 중복 여부 파악이 어려움
- **정보시스템 변경 및 유지보수 곤란**
  - 변경·유지보수 시 데이터 의미 파악이 어렵고, 새로운 정보 요건 반영 시 기존 데이터 활용 가능 여부 파악이 어려워 유지보수에 많은 노력
#### 나. 데이터 문제점의 원인
- **동시 다발적인 정보시스템 개발**
  - 시스템 간 상호 연관성 증대로 관련 정보시스템을 **동시에 개발**하는 경향
  - 전사적 표준 정책 없이 단위 시스템 위주로 표준 정책을 수립하고 업무 기능 구현에 초점을 맞춰 개발
- **전사 데이터 관리 마인드 미형성**
  - 데이터 관리 주체가 단위 시스템의 개발자, 운영자 중심 → 단위 업무 지원에 초점
  - 여러 시스템의 데이터를 복합적으로 활용하는 경우가 많으므로 전사 데이터의 체계적 관리 마인드 필요
- **전사 데이터 관리 인력 부재**
  - 개발 단계 : 개발 수행사의 품질 관리 조직을 통해 표준 관리
  - 유지보수 단계 : 표준과 준수 관리를 맡은 전문 데이터 관리 인력 없이 **개별 유지보수 인력에 의존**
- **전사 데이터 표준 관리 도구 부재**
  - 표준 관리, 준수 체크, 조회 및 활용 등 많은 자동화 지원이 필요
  - 개발 시에는 수작업으로 적용·체크했으나, 운영 단계에서 수작업에 가까운 표준 관리는 많은 애로 사항
#### 다. 데이터 관리 개선 방안
- 데이터 통합과 데이터 품질 달성을 위해 **전사적인 데이터 표준화 활동** 필요
  - 데이터 표준화, 규격화를 위한 기본 방침 설정
  - 전사적인 정보 공유를 위해 유지되어야 할 공통 데이터 요소의 도출
  - 전사적인 데이터 요소 등록 및 관리 체계 구축
  - 개발 및 유지보수 시 승인된 데이터 요소를 활용하여 개발 효율성 및 데이터 공유성 향상
### 2. 데이터 표준화 기대 효과
- 현업 사용자는 정확한 데이터를 사용하고 올바른 의사결정 → 기업 경쟁력 확보
- **명칭의 통일로 인한 명확한 의사소통의 증대**
  - 동일한 데이터에 동일한 명칭 사용 → 개발자-현업, 운영자-현업, 운영자-운영자 등 다양한 계층 간 명확하고 신속한 의사소통
- **필요한 데이터의 소재 파악에 소요되는 시간 및 노력 감소**
  - 새로운 정보 요건 발생 시 데이터의 의미, 위치 등을 신속하게 파악 → 원하는 시기에 정확한 정보 전달
- **일관된 데이터 형식 및 규칙의 적용으로 인한 데이터 품질 향상**
  - 입력 오류 방지로 품질 향상, 표준에 근거한 활용으로 잘못된 데이터 활용에 의한 의사결정 오류 감소
- **정보시스템 간 데이터 인터페이스 시 데이터 변환, 정제 비용 감소**
  - 전사적으로 표준에 의해 관리되면 다른 시스템의 데이터를 별도 변환·정제 없이 그대로 활용 → 별도 비용 없음
## 제2절 데이터 표준화 개념
### 1. 데이터 표준화 정의
- 시스템별로 산재해 있는 데이터 정보 요소에 대한 **명칭, 정의, 형식, 규칙**에 대한 원칙을 수립하여 **전사적으로 적용**하는 것
- 데이터의 정확한 의미를 파악하게 할 뿐 아니라 데이터에 대한 **상반된 시각을 조정**하는 역할
[[img:G3-01]]
#### 가. 데이터 명칭
- 해당 기업 내에서 데이터를 **유일하게 구별**해 주는 이름 → 명칭 표준화는 **동음이의어 및 이음동의어의 조정**이 필요
- **유일성**
  - 해당 개념을 유일하게 구분해 주는 이름, 하나의 개념에는 **오직 하나의 명칭**만 허용
  - 예1) 고객 계좌번호, 고객 구좌번호 → '고객 계좌번호'로 통일
  - 예2) EMAIL 주소, EMAIL → 'EMAIL 주소'로 통일
- **업무적 관점의 보편성**
  - 업무적 관점에서 보편적으로 인지되는 이름, 구성원들이 가장 많이 사용하는 업무 용어를 그대로 사용
- **의미 전달의 충분성**
  - 이름만으로 데이터의 의미 및 범위가 파악될 수 있어야 함
  - 관점에 따라 의미가 달라질 수 있는 이름은 **수식어** 등으로 구체화
#### 나. 데이터 정의
- 해당 데이터가 의미하는 **범위 및 자격 요건**을 규정
- 업무 관점에서 범위와 자격 요건을 명시, 명칭만으로 전달하기 어려운 기타 사항 전달
- **데이터 소유자를 결정하는 기준**
- 기술 시 고려 사항
  - 관련 업무를 모르는 **제3자의 입장**에서 기술
  - 서술식 정의만으로 전달이 어려우면 **실제 발생할 수 있는 데이터 값**도 함께 기술
  - 데이터 명칭을 그대로 서술하거나 약어·전문 용어를 이용한 정의는 가급적 사용하지 않음
#### 다. 데이터 형식
- 데이터 표현 형태의 정의를 통해 **입력 오류와 통제 위험을 최소화**
- 업무 규칙 및 사용 목적과 일관되도록 정의
  - 데이터 타입 : Numeric, Text, Date, Char, Timestamp 등
  - 데이터 길이 및 소수점 자리
- 정의 시 고려 사항
  - **도메인**을 정의하여 표준에 적용함으로써 성격이 유사한 데이터 간의 형식 통일
  - 최대값 또는 최대 길이가 고정되어 있지 않으면 **충분히 여유 있게** 정의
  - 특수 데이터 타입(CLOB, Long Raw 등)은 조회, 백업, 이행 등에 제약이 많으므로 **가급적 사용하지 않음**
#### 라. 데이터 규칙
- 발생 가능한 데이터 값을 **사전에 정의**하여 입력 오류와 통제 위험을 최소화
- 데이터의 **정합성 및 완전성** 향상
- 유형
  - **기본 값** : 입력을 생략했을 때 데이터 타입에 따라 자동으로 입력되는 값 (예: Numeric은 '0', Char는 '스페이스')
  - **허용 값** : 업무 규칙과 일관되게 입력 가능한 값을 제한 — 표준 코드 중 항목별로 가질 수 있는 코드 값을 사전 정의 (예: 표준 코드 01~10 중 특정 항목은 01, 03, 05만 허용)
  - **허용 범위** : 입력 가능한 값을 범위로 제한 (예: 1~5 외에는 입력 불가)
### 2. 데이터 표준화 구성요소
- 전사적 데이터 표준화를 위한 구성 요소 : **데이터 표준, 데이터 관리 조직, 데이터 표준화 절차**
[[img:G3-02]]
#### 가. 데이터 표준
- 이상적으로는 데이터 모델과 데이터베이스의 모든 오브젝트가 대상이나, **관리할 필요가 있는 오브젝트만** 대상으로 하는 것이 효율적
- 일반적인 관리 대상 : **용어, 단어, 도메인, 코드**
- **표준 용어**
  - 업무 용어의 표준을 정의하여 혼란을 방지하고 원활한 커뮤니케이션 촉진
  - **업무적 용어** : 일상 업무에서 사용하는 용어(보고서, 업무 매뉴얼 등)
    - 데이터 표준화는 주로 데이터베이스 객체에 국한되므로 반드시 필요한 것은 아님
    - 그러나 데이터베이스 용어가 대부분 현업 용어를 수용하므로 표준화 작업을 수월하게 해 주는 장점 (예: 색인(INDEX))
  - **기술적 용어** : 정보시스템에서 사용하는 용어 — 데이터 모델·스키마의 테이블명, 칼럼명 등
    - 용어 표준화 = 업무적 용어를 정보시스템에 반영하기 위해 **기술적 용어로 전환하고 일관되게 유지·관리**하는 것
    - 테이블·칼럼 한글명은 대부분 업무 용어를 따르지만, 데이터베이스 제약(테이블명 중복 불허, 길이 제약)과 표준 단어 사용에 따라 업무 용어와 다르게 정의될 수 있음
- **표준 단어**
  - 표준 용어를 구성하는 단어의 표준을 정의하여 용어의 한글명과 영문명을 일관되게 정의
  - 목적
    - 동일 개념을 의미하는 용어(표준 용어)의 **중복 생성 예방** — 예) '고객', '계좌'를 표준 단어로 정의하면 '고객 계좌'만 표준, '고객 구좌'는 배제
    - 표준 용어 **영문명 작성 기준** — 테이블·칼럼의 한글명만 작성하면 영문명은 표준 단어에 의해 자동 결정
- **표준 도메인**
  - **칼럼에 대한 성질을 그룹핑**한 개념
  - 크게 문자형, 숫자형, 일자형, 시간형 / 세부적으로 명, 주소, ID(문자형), 금액, 율, 수량(숫자형) 등
  - 동일한 성질의 칼럼의 **데이터 타입 및 길이를 일관되게 관리**, 칼럼 값에 대한 공통 검증 규칙 적용 가능
- **표준 코드**
  - 도메인의 한 유형으로, **특정 도메인 값(코드값)이 이미 정의되어 있는 도메인**
  - 다른 표준과 달리 **데이터 값(코드값)까지 미리 정의**해야 함
- **기타 데이터 표준 관련 요소**
  - 필요에 따라 주제영역, 관계명(데이터 모델)과 데이터베이스, 스키마, TABLESPACE, INDEX, CONSTRAINT 등(데이터베이스)의 표준도 관리
#### 나. 데이터 표준 관리 조직
- 표준 원칙, 표준, 준수 여부 관리 등을 위해 **데이터 관리자(DA, Data Administrator)** 역할 요구
- 데이터 관리자 : 기업·조직 내 데이터에 대한 **정의, 체계화, 감독 및 보안** 업무 담당
  - 전반의 데이터 관리를 총괄하고 정보 활용에 대한 **중앙 집중적 계획 수립 및 통제**
##### 1) 데이터 관리자 주요 역할
- **데이터에 대한 정책과 표준 정의** : 표준화 원칙 및 표준 정의, 변경·추가 시 최종 승인, 시스템별 표준 준수 여부를 주기적으로 체크
- **부서 간 데이터 구조 조율** : 단위 시스템·조직에 명확한 관리 기준 제시, 부서 간 이견 발생 시 전사 관점에서 데이터 구조 제시
- **데이터 보안 관리** : 보안 정책 수립, 준수 여부 체크, 시정 조치 요구
- **데이터 모델 관리** : 의사소통 도구인 데이터 모델을 물리적 변경 시점에 동일하게 관리 → 업무 협의 시 신속한 의사결정
- **데이터의 효율적인 활용 방안 계획** : 활용상의 문제점을 지속적으로 체크하여 활용 방안 수립·시행
##### 2) 데이터 관리자 세부 역할
- 전사 데이터 관리자, 업무 데이터 관리자, 업무 시스템 데이터 관리자로 구분

# 제2장 데이터 표준 수립
## 제1절 데이터 표준화 원칙 정의
### 1. 데이터 표준화 요구 사항 수집
- 현업 및 개발자로부터 표준 관련 요구 사항을 **인터뷰 및 설문조사** 등으로 조사 → 전사 표준 대상 후보 식별, 개선점 도출 자료 마련
- 담당 영역의 틀을 벗어나 **전체적인 관점 및 제3자의 관점**에서 기술하도록 유도
- 유효한 방법 : 자신의 영역과 다른 영역(주제 영역 간, 정보시스템 간)의 **인터페이스 부분**에서 발생하는 불편 사항 및 개선 사항 파악
- 해당 영역을 오래 관리한 담당자보다 **익숙하지 않은 관련자의 관점**이 더 유용 — 담당자는 이미 익숙해져 표준의 필요성을 덜 느낌
[[img:G3-04]]
### 2. 현행 데이터 표준 원칙 분석
- 현행 정보시스템의 표준 원칙 및 표준을 수집하여, 식별된 표준의 관리 대상 및 현황 파악
#### 가. 현행 데이터 표준 원칙 수집
- **현 정보시스템 개발 지침 문서 및 데이터 표준의 확보**
  - 기존 시스템 개발 당시의 개발 지침 문서(각종 오브젝트의 명명 규칙 등)와 데이터 표준으로 수집
  - 정의된 표준 검토로 표준 대상별 관리 항목 파악 가능
- **현행 정보시스템 모델의 분석**
  - 데이터 모델·스키마에 보이는 오브젝트의 **정의 패턴 분석**으로 적용 원칙을 유추
  - 단, 유추할 수 있는 대상 및 관리 항목은 상당히 **제한적**
#### 나. 데이터 표준 원칙 사용 현황 분석
- 수집 자료를 토대로 현행 표준 대상 및 관리 항목 도출
- 표준 대상별로 어떤 시스템에 적용하는지, 어떤 관리 항목을 관리하는지, 어떻게 상이하게 관리되는지 조사 → 개선점 도출 자료

### 3. 데이터 표준 개선 방안 정의
- **현행 데이터 표준 사용 현황 명세서**와 **표준화 요구 사항 정의서**를 토대로 표준 대상별 문제점 및 개선 방안 도출
- 반드시 **전사적인 관점**에서 접근, 전사적 관리 필요성을 검토하여 표준 대상·관리 항목을 신규 정의하거나 제외

| 명칭의 구조 | 테이블명 및 칼럼명이 특성·부가 정보를 표시하도록 단어 조합 구조를 명시 — 예) 수식어 + [수식어] + 속성 유형(금액, 건수, 코드 등) |
| 명칭에 대한 허용 길이 | DBMS의 물리적 길이 제약 때문에 표준 용어의 허용 길이 명시 |
| 명칭 표준화에 대한 기준 | 유사 개념의 단어/용어가 복수일 때 표준 선택 기준 — 예) 일련번호, ID, SEQ → ID로 표준화 |
| 명칭에 대한 예 | 허용 길이, 구조 체계, 표준화 기준 등을 준수한 샘플 명시 |
- **데이터 형식 정의에 대한 기준** : 표준 용어를 칼럼으로 쓰는 경우나 표준 도메인, 표준 코드의 형식 정의 기준
  - 명칭 표준화 기준을 정할 때 형식도 함께 정의 → **명칭 결정과 동시에 형식도 자동 결정**
  - 예1) 표준 용어 : ID의 데이터 형식은 8자리 텍스트
  - 예2) 표준 도메인 : '번호'성 도메인의 데이터 형식은 텍스트
- **기타** : 대상별 고유 특성에 대한 원칙 (예: 표준 도메인의 데이터 타입 결정 기준)
##### 2) 주요 데이터 표준 대상별 지침의 일반적인 구성
- **표준 단어**
  - 한글명·영문명의 문자 허용 여부 또는 사용 조건
  - 대소문자 사용 규칙
  - 한글명·영문명 허용 길이
  - 합성어(단어의 조합으로 이루어진 단어) 정의 지침
  - 접두사 처리 방안
  - 동음이의어/이음동의어 허용 여부 및 처리 방안
- **표준 용어**
  - 데이터 명칭의 구조 체계
  - 한글명·영문명 허용 길이
  - 테이블·칼럼명으로 사용할 때 준수할 특이 명명 규칙
  - 칼럼명으로 사용할 때 형식 표준화 기준 및 표준 도메인 적용 여부
- **표준 도메인**
  - 데이터 형식 표준화 기준
- **표준 코드**
  - 명칭의 구조 체계 및 명명 기준
  - 데이터 형식 표준화 기준
  - 코드번호 체계 정의 규칙
##### 3) 데이터 표준 개발 지침 작성 시 유의사항
- 현행 지침을 그대로 유지하는 것이 가장 바람직하나, 단위 시스템을 벗어나 다른 시스템에도 적용 가능하도록 **범용성** 고려
- DBMS마다 테이블·칼럼 **물리명 길이**가 다름 → 영문명 허용 길이는 모든 대상 DBMS에 적용 가능하게, 어려우면 영문 축약명 추가 정의나 뷰(View) 사용 등 대안
- DBMS마다 **데이터 타입**이 다름 → 서로 다른 DBMS에 어떻게 적용할지 방안 고려
  - 방안 1) 형식을 '문자 1자리', '숫자 15.2자리' 등 **논리적으로 기술**하고, 논리 형식과 DBMS별 물리 타입 간 **변환 Map** 정의
  - 방안 2) **특정 DBMS 기준**의 타입으로 정의하고, 기준 DBMS와 기타 DBMS 타입 간 **변환 Map**을 정의
## 제2절 데이터 표준 정의
### 1. 표준 단어(Word) 사전 정의
- 기존 데이터 모델 및 용어집에서 사용 중인 **모든 단어를 추출**
- 단어 종류와 유형을 분류하고 업무 정의 및 용도를 고려하여 표준 단어 정의
- **이음동의어, 동음이의어 처리**에 주의
- 표준화 원칙을 참고하여 **영문명과 영문 약어명** 정의
#### 가. 표준 단어 사전
- 단어 : 문법상 일정한 뜻과 구실을 가지는 말의 **최소 단위**
- 표준 단어 사전 : 기업에서 업무상 사용하며 일정한 의미를 갖는 최소 단위의 단어를 정의한 사전
- 같은 단어를 서로 다른 의미로 쓰거나 한 단어에 다양한 의미를 부여하는 문제 방지
##### 1) 표준 단어 관리 기준
- **표준성** : 정보시스템이나 일반 업무에서 사용되는 단어 중에서 추출, 너무 업무적인 용어는 최소화하여 정보시스템 특성에 부합
- **일반성** : 사전적 의미와 크게 다르지 않아 **일반인도 이해**할 수 있어야 함
- **대표성** : 동의어를 가질 수 있으며, 표준 단어는 비슷한 의미의 **동의어들을 대표**할 수 있어야 함
##### 2) 표준 단어 작성 형식
- 전사적으로 관리하는 **엔터티와 속성을 개별 단위**로 추출
- 동음이의어·이음동의어를 정비한 후 **논리명(한글명)**을 기준으로 **물리명(영문명, 영문 약어명)**, 유사 용어까지 함께 정리
- 개별 단어 외에 **동의어, 유의어, 반의어** 등 단어 간 구조도 정의
[[img:G3-08]]
#### 나. 표준 단어 정의
- 시스템별로 혼재된 모든 용어를 **단어 단위로 분할**하여 도출
[[img:G3-09]]
##### 1) 현행 용어 수집
- 모든 정보시스템의 데이터 모델 또는 테이블·칼럼 정의서를 분석하여 현행 용어의 한글명 및 영문명 수집
- 목적은 단어 분할과 영문 약어명 도출 → 상용 패키지처럼 **한글명이 없는 데이터 모델은 수집 대상에서 제외**
##### 2) 단어 분할
- 업무상 사용되며 일정한 의미를 갖는 **최소 단위**로 분할
- 한글명과 영문 약어명을 함께 도출해야 하므로 **영문명도 같이 분할되는지** 고려
- 단독으로 분할되는 **숫자는 표준화 대상에서 제외**
[[img:G3-10]]
##### 3) 단어 정렬
- 의미가 동일한 단어들 중 하나의 **대표 단어**를 표준으로 선정하고 영문 약어명 선택
- 최종 단어들은 **한글명과 영문 약어명 모두 유일**해야 함
- 이용 가능한 기법
  - 한글명이 같은 단어와 이음동의어를 취합한 후 **활용 빈도가 가장 많은 한글명**을 표준으로 선택 — 이음동의어는 **영문 약어명이 같은 단어** 검색으로 찾음
  - 한글명이 같은 단어와 이음동의어를 통틀어 **가장 많이 나타나는 영문 약어명**을 선택
  - 동음이의어는 활용 빈도가 낮은 의미의 단어에 대해 같은 의미의 **다른 한글명**을 표준으로 선택
[[img:G3-11]]
[[img:G3-12]]
##### 4) 표준 단어 사전 정의
- 표준으로 선택한 모든 단어의 한글명 및 영문명을 사전에 등록
- 의미는 유사하나 각기 다른 표준으로 등록한 단어 → **유사어**로 등록
- 표준으로 선택되지 않은 나머지 이음동의어 → **금칙어**로 등록·관리
- 향후 검색을 위해 관련 표준 용어도 함께 기술
#### 다. 표준 단어 정의 시 고려사항
- 최소 단위를 기준으로 하되, 사용 빈도가 높은 조합이나 조합이 **고유한 의미**를 가지면 하나의 표준 단어로 정의하는 것이 유리 — 예) 신용카드, 선하증권
- 대부분의 DBMS는 물리명 첫 글자를 **알파벳**으로 시작하도록 제약 → 영문명도 반드시 알파벳으로 시작 — 예) 1순위 → RNK1, 2개월 → M2
- 동음이의어가 많으므로 **사용 빈도가 높은 것**을 표준 단어로, 낮은 것은 다른 단어와 조합하여 표준 단어로 정의
- 접두어, 접미어 같은 **한 자리 단어**는 가급적 배제하고 앞뒤 단어와 조합하여 정의

### 2. 표준 도메인(Domain) 사전 정의
- 업무적 용도, 사용 빈도, 데이터의 물리적 특성 등을 고려해 도메인을 분류하고 **도메인별 데이터 타입** 부여
- 도메인 종류 : 코드성 도메인, 숫자 도메인, 날짜 도메인, 문자 도메인 등
#### 가. 표준 도메인 사전
- 도메인 : 속성에 정의된 조건을 만족시키는 **값의 범위**
- 표준 도메인 : 전사 데이터 중 논리적·물리적으로 **유사한 유형의 데이터를 그룹화**하여 그 그룹의 데이터 유형과 길이를 정의한 것
- 하나의 도메인은 여러 속성에 중복적으로 사용될 수 있음
##### 1) 표준 도메인 관리 기준
- **표준성** : 전사 차원에서 **공통적으로 사용되는 속성**을 대상으로 정의 — 예) 은행 계좌번호는 하위 업무·상품에 따라 다르지 않으므로 표준 도메인으로 정의
- **유일성** : 동일한 내용의 중복 도메인이 서로 다른 이름으로 선언되지 않도록 관리
- **업무 지향성** : 지나치게 일반화하기보다 **업무 특성을 충분히 반영** — 예) 계좌번호 도메인은 '-' 없이보다 의미를 나타내도록 '-'를 이용해 표현
##### 2) 표준 도메인 작성 형식
- 모든 데이터 속성 혹은 대표 속성 중 DBMS에 **동일한 형태로 구현되는 속성**들을 추출하여 그룹화
- 모든 속성은 임의의 도메인에 할당되어야 하며, **하나 이상의 도메인에 복수로 할당되면 안 됨**
- 속성과 도메인은 상호 매핑하여 관리, 새 속성 추가 시 도메인 선정·등록 권장
- 도메인 삭제는 **해당 도메인을 사용하는 속성이 없을 때만** 가능
[[img:G3-15]]
#### 나. 표준 도메인 정의
- 시스템별로 혼재된 칼럼의 칼럼명, 데이터 타입, 길이 등을 정리하여 정립
[[img:G3-16]]
##### 1) 현행 용어 정보 분석
- 데이터 모델 또는 칼럼 정의서로 현행 용어의 용어명과 데이터 타입 정보를 수집한 뒤 **물리적으로 유사한 유형**의 용어들을 그룹화
  - 같은 시스템의 데이터 모델에서 추출된 현행 용어를 유일하게 추출 — 한글명, 영문명, 데이터 타입 및 길이 모두 일치하는지 확인
  - **데이터 타입과 길이가 동일한** 용어들을 검색하여 그룹핑
  - 용어명 중 **끝 쪽 단어**를 기준으로 그룹핑
##### 2) 표준 도메인 정의
- 그룹핑된 유사 속성 용어의 의미에 따라 도메인명을 정하고 데이터 타입 및 길이 정의
  - 가급적 **업무적으로 의미가 있는 도메인명** 부여 — 예) ID, 증권번호, 일자, 일시, 주소, 여부, 환율(O) / 문자1, 문자2, 숫자12(X)
  - 호환성 및 범용성을 위해 그룹 용어들의 데이터 타입 길이 중 **가장 큰 길이**를 표준으로
#### 다. 표준 도메인 정의 시 고려사항
- 어느 도메인에도 속하지 않는 칼럼이 있을 수 있으므로 **모든 용어를 포괄하는 도메인을 만들 필요는 없음**
- 데이터 형식을 어떻게 정의하고 각기 다른 DBMS에 어떻게 물리적으로 적용할지 방안 고려
- 도메인을 도출하면서 **동일한 용어로 판명된 현행 용어들을 별도로 기록**하여 향후 표준 용어 통일 시 참고
### 3. 표준 코드(Code) 사전 정의
- 수집된 용어에서 코드를 선별하여 현 코드의 코드값 조사
- 통합 요구 사항과 필요성에 따라 통합 대상을 파악하고 표준 코드 정의, **현 코드와 매핑 설계**
- 표준 코드별 **오너십(Ownership)**을 정의하여 수정·삭제 권한 관리
#### 가. 표준 코드 사전
- 산업별로 법·제도적으로 부여되어 공통적으로 쓰는 코드와 **기업 내부에서 정의한 코드** 모두 포함
##### 1) 표준 코드 관리 기준
- **재사용성** : 자체 정의보다 **표준화 기구나 정부, 공공기관에서 정의한 코드를 재사용**하는 것이 이해력을 높이고 관리를 용이하게 함
- **일관성** : 업무 범위 내에서 가능한 한 **유일하게 정의** — 사용 형태나 업무 범위에 따라 중복 정의하면 코드 데이터의 중복과 불일치 발생
- **정보 분석성** : 가능한 범위의 데이터는 **모두 코드화** — 텍스트 직접 입력을 최소화하여 분석 가치 없는 데이터 생성 방지
##### 2) 표준 코드 작성 형식
- 전사 코드를 추출·정의하고, 동일한 값을 가진 코드는 통합하여 **단일화**
- **표준화 팀**이 엄격한 기준으로 관리, 사용자가 임의로 코드 체계를 생성·수정해서는 안 됨
- 코드는 도메인과 밀접하게 연관하여 관리하나, 도메인에 값의 범위가 명확히 정의된 경우(예: '여부'는 'Y/N')는 **특별히 코드화하지 않아도 됨**
[[img:G3-17]]
#### 나. 표준 코드 정의
- 시스템별 모든 코드를 수집하여 동일 코드를 파악·통합하여 정의
##### 1) 현행 코드 수집
- 코드 관리 형태 3가지에 따라 수집 방법을 달리함
  - **단독 코드 테이블** : 하나의 코드를 하나의 테이블에서 관리 — 코드 번호, 코드값 외에 부가 정보를 관리하는 경우가 많아, 코드인지 **정보성 데이터(ID로 관리되는 정보)**인지 구분한 뒤 추출 여부 판단
  - **통합 코드 테이블** : 복수 코드를 하나의 통합 테이블에서 관리 — 코드 유형 번호, 코드명, 코드 구조, 코드 번호, 코드값과 관리 정보(생성 일자, 폐지 일자, 오너십 등). **모두 수집**
  - **애플리케이션 정의** : DB가 아닌 애플리케이션에서 정의·관리 — 소스 없이는 확보가 어려워 사용자 인터페이스 조회나 코드성 칼럼의 데이터 값 추출 등 **간접적 방법**으로 수집
- 코드는 테이블에서 값이 누락되거나 애플리케이션에서 정의되는 이유로 단어, 도메인, 용어와 달리 **수집 시 누락될 가능성이 많음** → 다음 방법으로 정확히 파악
  - **코드 데이터 값 수집** : 코드 테이블, 통합 코드 테이블, 애플리케이션 UI를 통해 수집
  - **코드성 칼럼 파악** : 코드 정보를 저장하는 칼럼 파악 — 코드 저장 칼럼인지 정보성 데이터 참조 칼럼인지 명확히 구분
  - **수집된 코드에 대한 사용처 파악** : 코드성 칼럼에 저장된 값과 수집된 코드 번호를 비교·검증하여 누락 코드 확인·추가 수집
##### 2) 현행 코드 상세 분석
- 동일하거나 통합 가능한 코드 식별
  - 코드값이 일치하는 코드 인스턴스를 가진 코드를 찾아 모든 인스턴스를 확인·비교
  - 대상 코드가 너무 많으면 **업무 기능별로 분류**한 후 분류 단위로 분석
##### 3) 표준 코드 정의
- 통합 대상 코드의 인스턴스를 정련하여 통합
- 통합 대상이 없는 코드는 현행 인스턴스를 **그대로 유지**하는 것이 일반적
- 통합 대상의 코드 번호가 서로 다르면 **새로운 코드 번호**를 부여하여 정의
#### 다. 표준 코드 활용
- 향후 모든 정보시스템은 표준 코드를 사용해야 함
- 일부 업무에서 범위를 한정해 일부 코드값만 쓰면 표준 코드로부터 **파생 코드**를 정의하여 사용
  - 파생 코드의 코드 번호, 코드값은 **반드시 표준 코드에 정의**되어 있어야 함
  - 파생 코드에 인스턴스를 추가하려면 **표준 코드에 먼저 정의**
[[img:G3-18]]
#### 라. 표준 코드 정의 시 고려사항
- 향후 **확장성**을 고려하고, 여러 업무에서 쓸 수 있도록 통합 코드로서의 일관성 유지
- 운영 중 코드값이 변경되면 기존 데이터 유지를 위해 기존 코드값을 **삭제하지 않고 사용 중지 상태**로 관리하고 새 코드값을 신규 정의
- 도출하면서 파악한 **표준 코드-현행 코드 간 변환 매핑 정보**를 별도 기록하여 데이터 이행 시 참고
### 4. 표준 용어 사전 정의
- 단어, 도메인, 코드 표준이 정의되면 이를 바탕으로 표준 용어 구성
- 단어 조합, 도메인 분류, 데이터 타입 길이, 코드값 등을 기준으로 업무적·IT적으로 무리가 없는지 검토
- 검토 과정에서 누락된 단어, 도메인, 코드를 확인하고 보완
[[img:G3-19]]
#### 가. 표준 용어 사전
- 용어 : 업무에서 자주 사용하는 **단어의 조합**
- 표준 용어 : 전사적으로 사용하는 **엔터티와 속성**을 대상으로 표준 단어를 조합하여 정의
- 단어는 개별적이나 용어는 업무와 조직의 성격에 따라 조합이 달라질 수 있음
- 서로 다른 업무 간 의사소통 시 용어 이해 부족으로 생기는 문제 최소화
##### 1) 표준 용어 관리 기준
- **표준성** : 같은 기업 내부라도 업무별로 같은 의미를 다른 용어로 쓰는 경우가 매우 많음 → 용어 표준화로 전사 차원의 혼란 최소화
- **일반성** : 지나치게 업무 관점에서만 정의되어 이해하기 힘들거나 혼란을 초래해서는 안 됨 — 일반적 의미와 전혀 다르게 쓰인 용어는 대체하고 새로운 용어 개발 자제
- **업무 지향성** : 업무 범위 내에서 약어를 쓰거나 내부적으로 정의하여 쓸 수 있으나 **지나친 약어 사용**은 이해도를 떨어뜨리므로 주의
##### 2) 표준 용어 작성 형식
- 엔터티와 속성을 대상으로 표준 단어를 조합하여 생성
- **엔터티 용어 사전**과 **속성 용어 사전**으로 구분하여 관리
- 각 용어는 **논리명(한글명)과 물리명(영문명)**을 가지며, 용어 범위 및 자격 형식 등을 설명
[[img:G3-20]]
#### 나. 표준 용어 정의
- 모든 현행 용어를 수집하고 표준 단어·도메인·코드 사전을 참조하여 표준 용어 도출
[[img:G3-21]]
##### 1) 현행 용어에 대한 표준 단어 도출 및 표준 용어 정의
- 표준 용어 도출은 **단어 수준의 표준화**로 이루어짐
  - 현행 용어 분할 → 구성 단어 도출 → 유사 단어 검색 → 표준 단어 찾기 → 표준 단어 조합 = 표준 용어
- 영문명은 표준 단어의 조합으로 **자동 부여**
##### 2) 표준 단어에 대한 도메인/코드 정의
- 도메인 도출 시 별도 관리했던 정보로 표준 단어의 도메인 정의 — 현행 용어가 관련된 표준 도메인을 찾아 도출된 표준 용어에 적용
- 표준 코드도 유사한 방법으로 정의
#### 다. 표준 용어 정의 시 고려사항
- 표준 원칙에서 정한 한글명·영문명 **허용 길이**를 넘지 않도록 함
- 영문명 길이가 문제면 한글명을 변경하거나, 구성 단어 일부를 조합하여 하나의 표준 단어로 등록해 **영문명을 축약**
- 표준 용어가 너무 길면 **두 개의 표준 용어를 복합**하여 생성하는 방법도 고려
## 제3절 데이터 표준 확정
### 1. 데이터 표준 검토
- 데이터 관리자가 정의한 표준 단어·도메인·코드·용어 사전을 확인하고, 현재 사용 용어로 정확히 정의되었는지 확인하여 **승인 처리**
#### 가. 데이터 표준 검토 계획 수립
- 검토 대상 : 표준 단어 사전, 표준 도메인 사전, 표준 코드 사전, 표준 용어 사전 등
- 검토 기준 : **전사 데이터 표준 기본 원칙 및 대상별 지침**을 근거로 작성
- 주요 검증 기준
  - **유일성** : 물리적·의미론적으로 유일한지 — 예) 단어 사전 내 동음이의어 존재 여부, 용어 사전 내 이음동의어 존재 여부
  - **완전성** : 대상별 필수 입력 사항이 전부 정의되었는지 — 예) 표준 단어의 한글명과 영문 약어명
  - **정확성** : 대상별 입력 사항이 충실히 입력되었는지 — 예) 표준 용어의 정의
  - **범용성** : 여러 정보시스템에서 적용 가능한지, 향후 개발할 시스템에 적용할 수 있는지 — 예) 표준 도메인 데이터 타입의 타당성
#### 나. 데이터 표준 검토
- 검토 기준 및 대상 산출물을 준비하여 참여 대상자에게 배포
- 장소, 시간, 장비 등을 준비하고 담당자별 역할을 충분히 주지
- 진행자는 이슈에 대해 결론 도출을 위한 **토론이 발생하지 않도록 이슈 목록으로 정리**하고 일정 내에 마치도록 주의
- 세션 종료 후 결과를 양식에 정리
- 결과가 정리되면 표준 대상별 **보완 목록** 작성
  - 지적 사항만이 아니라 **함께 변경되어야 할 대상**도 기록
  - 특히 **표준 단어, 도메인, 코드의 변경은 표준 용어에 영향**을 미침
[[img:G3-22]]
[[img:G3-23]]
#### 다. 데이터 표준 보완 및 승인
- 검토 결과, 보완 목록, 보완 사항이 반영된 표준을 준비·배포
- 보완 목록에 준하여 반영 여부 확인, 미반영 사유가 타당하지 않으면 보완 조치
- 보완 사항이 모두 반영된 것을 확인하면 종료하고 **전사 데이터 관리자의 승인**을 득함
### 2. 데이터 표준 공표
- 확정된 표준을 배포하여 전사 시스템에 적용 가능하도록 하고, 이해와 적용을 위한 교육 수행
#### 가. 데이터 표준 배포
- 승인을 득한 표준은 **데이터 표준 관리 도구에 등록**하여 전사 모든 사용자가 조회할 수 있게 하고, 개발 관련자들이 표준을 준수하여 개발할 것을 **공지**
#### 나. 데이터 표준 교육
- 사용자 및 운영자 교육 훈련 계획 수립, 표준 지침 및 관련 교육 교재 작성, 교육 수행
# 제3장 데이터 표준 관리
## 제1절 데이터 표준 관리
### 1. 데이터 표준 관리 개요
- 표준화 작업 절차 이후, 표준 정의 단계에서 수립된 표준에 근거하여 **관리 프로세스**를 정립하여 표준이 관리되도록 함
### 2. 데이터 표준 관리 프로세스 유형
- 기본적으로 꼭 필요한 프로세스
  - 개발·운영 과정에서 **표준의 신규 요건**이 발생한 경우 이를 처리하는 프로세스
  - 표준이 **변경 또는 삭제**되는 경우 관련 표준화 요소, 데이터 모델, 데이터베이스, 관련 프로그램까지 **영향도를 분석**하는 절차와 처리 프로세스
  - 표준을 잘 **준수**하고 있는지 수시로 체크·확인하는 프로세스
## 제2절 데이터 표준 관리 프로세스
### 1. 데이터 표준 관리 프로세스 구성요소
- 전사적으로 일관된 형식과 규칙의 적용으로 품질을 향상하고, 관리 프로세스를 제대로 정의하여 표준을 지속적으로 유지
- 구성 요소 : **프로세스, 태스크, 역할과 담당 업무**가 명확하게 정의되어야 함
### 2. 구성요소별 설명
#### 가. 프로세스
- 표준의 신규·변경 발생 시 거쳐야 할 **전체 업무 프로세스**를 정의하여 표준이 잘 준수되게 하고, 항시 준수 여부를 확인·조치
[[img:G3-24]]
#### 나. 태스크
- **표준 신규/변경 요청**
  - 업무 담당자가 데이터 관리자에게 표준 단어, 표준 용어, 표준 도메인 등을 신규 또는 변경 요청
  - 표준 용어 신규·변경 시 구성 표준 단어나 표준 도메인이 없으면 **그 단어·도메인을 먼저 신규 요청**
- **표준 준수 검토**
  - 데이터 관리자가 요청 사항의 표준 준수 여부를 검토하고 결과를 업무 담당자에게 피드백
  - 요청 용어가 **용어 설명에 부합**하는지, **기존 용어의 의미와 중복**되는지 체크
